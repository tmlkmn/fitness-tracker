# CLAUDE.md — apps/mobile

@AGENTS.md

FitMusc's Expo app. The repo-root `CLAUDE.md` covers the web app and the `/api/v1` contract this app consumes; everything here is relative to `apps/mobile/`.

## Setup & commands

Own install, not an npm workspace — run these inside `apps/mobile`:

| Command | Purpose |
|---|---|
| `npm install` | Install (own `package-lock.json`; add Expo modules with `npx expo install <pkg>`) |
| `npx expo start` | Dev server — scan the QR code with Expo Go (same Wi-Fi, or `--tunnel`) |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run lint` | `expo lint` |
| `npx expo-doctor` | Dependency / config checks |
| `npx expo export --platform android` | Full bundle without a device (catches Metro resolution errors) |

`EXPO_PUBLIC_API_URL` (see `.env.local.example`) points the app at a backend; default is production `https://www.fitmusc.com`. Production data is real — the app is used with the owner's admin account.

## Architecture

- **Routes** (`src/app/`, expo-router): root `_layout.tsx` holds the providers and three `Stack.Protected` groups — signed out → `sign-in`; signed in but blocked → `blocked`; otherwise `(tabs)` (native tabs `(today)`, `calendar`, `progress`, `assistant`, `settings` — five is the Android maximum — one `Stack` per tab) plus pushed screens `day/[dayId]`, `shopping` (`?week=`) and the modals `progress-log` (`?id=` to edit), `sleep/[date]`, `meal-form` and `exercise-form` (`?dayId=` + `mealId` / `exerciseId` to edit), the AI modals under `ai/` (below), the pushed `notifications`, `notification-settings`, `reminders`, `sharing`, `shared/week/[weeklyPlanId]`, `shared/day/[dayId]` and the modals `reminder-form` (`?id=` to edit) and `share-week` (`?weeklyPlanId=`). Forms guard unsaved input with `useCloseGuard` (`src/hooks/close-guard.ts`, `usePreventRemove`) and call its `leave()` after saving. **Declare every new screen inside the signed-in `Stack.Protected` group** — an undeclared route is reachable without the guard. Past days are view-only, like the web (no completion toggles, water or sleep edits).
- **Session** (`src/lib/session.tsx`): better-auth `useSession` via `src/lib/auth-client.ts` (`@better-auth/expo`, cookie in SecureStore). A 401 from the API signs out; a 403 with an `AccessDenial` code (or `mustChangePassword` on the session user) shows the blocked screen. No purchases in the app — renewals and password flows open the web (`src/lib/web-links.ts`).
- **Origin**: Expo Go reports `exp://…` as `expo-origin`; `auth-client.ts` rewrites it to `fitmusc://`, the only app origin the server trusts. Never add `exp://` to the server's `trustedOrigins` in production — it would also accept password-reset redirects to any Expo Go bundle.
- **API** (`src/lib/api.ts`): `api<T>(path)` calls `/api/v1{path}` with the session cookie and throws `ApiRequestError { status, code }` (`code` = `ApiErrorCode` or `NETWORK`). Request/response types come from `@fitmusc/shared/api/{schemas,dto,errors}` — never redeclare them here.
- **Data** (`src/hooks/`): TanStack Query, 60s stale time, no retries on 4xx; completion toggles update the cached lists optimistically and go through the offline outbox (below). Meal / exercise updates are `PUT` — the server overwrites every column — so send the whole record (a meal's `icon` included) or the omitted fields are cleared (`src/hooks/edit.ts`). Query keys are `["entity.action", ...params]` like the web.
- **Offline** (`src/lib/outbox.ts`, `src/lib/offline-cache.ts`): meal / exercise / supplement completion toggles are queued in AsyncStorage (one entry per item — the latest state wins) and sent by `syncCompletion`. Offline or on a network error the optimistic state stays and the queue drains when the connection or the app comes back (`useOutboxSync`, mounted by the tabs layout); a 4xx rolls the tick back and drops it, a 5xx is retried 10 times. List queries lay unsent ticks over fresh data (`withPending`), so a refetch never undoes one. The query cache is saved per user (AsyncStorage, 3 days, `ai.*` excluded — `gcTime` matches) so the app opens offline with the last data, and while the server can't be reached the session falls back to the user the expo plugin cached in SecureStore. Sign-out clears the queue and that user's saved cache; another account signing in drops the previous queue. `OfflineBanner` (Today, day) shows offline / pending.
- **Notifications, reminders, sharing**: the Today header's bell (`NotificationBell`, unread count polled every 60 s) opens `notifications`, which marks everything read on open like the web's dropdown. Settings links to `notification-settings` (channels — account-wide —, quiet hours, week start), `reminders` (templates / meal + workout / custom via `reminder-form`; the phone's time zone is saved when none is set) and `sharing` (plans shared with the user → read-only `shared/week` / `shared/day`, and the user's active weeks → `share-week`, also reachable from the calendar's selected day). Past weeks can't be shared (`isWeekPast`, `src/lib/dates.ts`).
- **i18n** (`src/lib/i18n.tsx`): `use-intl` with the web's catalogs (`@fitmusc/shared/messages`). Reuse the web's keys; app-only strings go in the `mobile` namespace of both `tr.json` and `en.json`. Locale = the user's (`PUT /me/locale`), the device's before sign-in.
- **AI** (`src/hooks/ai.ts`, `src/components/ai.tsx`, `src/components/ai-results.tsx`): mirrors the web's AI surfaces. Short calls are plain requests — meal alternatives (`ai/meal-variation`), exercise alternatives + form tips (`ai/exercise`), the daily greeting (Today), progress analysis (Progress tab) and the coach chat (`assistant` tab). The analysis and the chat stream text through `apiStream()` (`src/lib/api.ts`, `expo/fetch`). Daily meals, a day's workout (or one section of it: `ai/workout?section=`, a "workout" job with `section` + `sectionLabel`, applied through `/ai/workout-section/apply`) and the weekly plan are **background jobs**: the option screens `ai/day-meals`, `ai/workout`, `ai/weekly` (`?date=`) POST `/ai/jobs` and `replace` themselves with `ai/job/[jobId]`, which polls, shows progress and then the result (approve → the `/ai/…/apply` endpoint, or "new suggestion" with the job's `input`). The job keeps running if the screen or app closes: a push (`tag: "ai-job"`, routed by `usePushNotifications` in `src/hooks/push.ts`) or the day / calendar `JobBanner` reopens it. Every AI button shows the feature's quota (`AiButton` / `QuotaBadge`). Targets: `weight-targets` (modal from the Progress target tile — start/target weight + the AI target suggestion) and `macro-targets` (from Settings — resolved targets + the AI macro calculator, which saves the *strategy* via `PUT /me/macro-strategy`). The web's gates apply here too: past days and weeks get no AI, the month gate (`useMonthGate`) and the empty-week gap block later weeks, and the weekly plan needs the profile fields the web requires. **The weekly plan is Monday-based** on the server (`dayOfWeek` 0 = Monday) regardless of the user's week start — `src/lib/ai-weekly.ts` computes the week and `pastDows` that way, and `pastDows` is recomputed when applying so a day that has passed since generation is never overwritten.
- **Push** (`src/lib/push.ts`): registers the Expo token after sign-in, unregisters before sign-out. Tapping any push opens its screen (`usePushNotifications`: AI jobs → `ai/job/[jobId]`, otherwise `data.url` / `tag` mapped by `src/lib/notification-links.ts`, which also serves the in-app list; web paths the app has no screen for open in the browser). Needs a physical device and an EAS `projectId` (`eas init`); Expo Go on Android has no remote push (use a development build).
- **Dates** (`src/lib/dates.ts`): `YYYY-MM-DD` strings throughout; arithmetic in UTC so the phone's zone or a DST switch never shifts a day; "today" is Europe/Istanbul (`todayStr()`), like the server. The week starts on the user's `weekStartsOn` preference.
- **Charts** (`src/components/charts.tsx`): `LineChart` / `BarChart` on `react-native-svg`, one series per chart (the card title names it, no legend), tap or drag to read a value. Series colours are `seriesColors` (`theme.ts`); plan-type colour + icon live in `components/plan-type.tsx` — workout/swimming/rest were validated as a categorical set on the dark surface, so re-check the trio before recolouring one.
- **Forms** (`src/components/form.tsx`): `DateField` / `TimeField` use `@react-native-community/datetimepicker` (compact inline on iOS, system dialog on Android). Decimal inputs accept a comma (TR keyboard), are normalized to a dot and validated with the shared zod schema before sending. The meal form (`src/app/meal-form.tsx`) mirrors the web's dialog: an emoji override (`meals.icon`, presets from `@fitmusc/shared/meal-icons`), the food reference (`src/components/food-reference.tsx` — preset foods by category plus the user's own `/user-foods`, added with a 0.25× portion step; each added food appends to the content and the macros and can be removed again) and, for a new meal, the picker. The picker's "Daily" tab lists saved AI daily plans; choosing one **replaces all of the day's meals** (`/ai/daily-meals/apply`, after a confirmation), like the web's Öğünlerim → apply to day.
- **Styling**: React Native `StyleSheet` with the web's dark palette (`src/lib/theme.ts`); dark mode only. Shared primitives in `src/components/ui.tsx`.
